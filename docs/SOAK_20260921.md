## 二、浸泡**发现并修掉**的一个系统性假红：`smooth.jerk_spike_ratio`

**85 轮里每一轮都报 `47722.67`，而锚点上界是 32 ⇒ 每次判 0 分。**

根因：旧口径的分母是 `median|Δv|`，而它**随参考平滑到什么程度变化** —— 参考越平滑，
它越接近 **f32 舍入噪声**。实测低到 **3.143e-07**，而 `max|Δv|` 是 `1.5e-02`
⇒ 比值爆到 47722。而同一批数据里**物理行为完全相同**的段只给出 **1.4**（跨 **34000×**）。

⇒ 分母换成**巡航速度**：`最大单拍速度变化 / 巡航速度`（无量纲）。

| | 旧口径 | **新口径** |
|---|---:|---:|
| 85 轮取值 | 47722.7（逐位相同） | **0.0142**（逐位相同） |
| 得分 | **0** | **96** |

⚠ 0.0142 是个**有物理含义的常数** —— S 曲线自身的台阶（"最大单拍速度变化 ≈
巡航速度的 1.4%"），不是噪声。新口径在真机上稳定在 0.0103~0.0212。

**修正效果**（同一轮 `full`）：

| | 平滑度与抖动 | 总分 |
|---|---:|---:|
| 修前 | 74.9 | 79.8 / B |
| **修后** | **97.2** | **82.0 / A** |

⇒ 之前报出的 `full` 成绩（78.3 / 77.8）**都被这个假红压低了约 2 分**。
**修正后 85 轮的均分是 81.45**（80.26~82.52，sd 0.42）。

## 三、浸泡抓到的一个**真缺陷**（被测系统，不是基准）

4 次失败**全部**是同一个错误、**全部**落在笛卡尔段：

```
LiteArmError: 收到 0x4E (笛卡尔规划应答) 但队列为空 —— 应答比请求多,
              固件与主机已错配 (已计数 extra_replies=1)
```

| 轮 | 时刻 | 该轮用时 |
|---|---|---|
| 50 | 04:34 | 109.5 s |
| 52 | 04:40 | 116.0 s |
| 63 | 05:23 | 116.0 s |
| 88 | 07:05 | 115.9 s |

**这是本项目早已记录、但一直没有真机证据的那条**：知识库里
「STM32 笛卡尔 N≥3 突发丢应答 —— 单槽 pending ⇒ 中段零应答、FIFO 错位」
当时的标注是 **"读码推演、未上真机"**。现在它在真机上被复现：**4.5% 的轮次**。

**要修的地方是固件与 host 的笛卡尔应答配对**（`cart_exec.c` 的 `cart_publish()`），
**不是基准**。基准这一侧已经改成：采样循环里捕获该错误、**记进段落、继续跑**
（它是被测系统的缺陷，不该让整轮基准崩掉）。

## 四、这份数据**没有**回答什么

- ⛔ **不能用来定锚点。** 89 个样本全部来自**同一台臂、同一天、同一固件**。
  锚点要的是与**机器无关**的参照（指令剖面 / 物理下界 / 固件保护阈值），
  或**跨机器跨固件**的分布。
- ⛔ **不能说明长时间可靠性**超过 6 小时。6 小时是个不短的窗口，但"没坏"不等于"不会坏"。
- ⛔ **笛卡尔那 4.5% 的根因未定位** —— 只确定了它稳定复现在笛卡尔段、错误形态一致。
  是每次都发生还是与温度/时序相关，本轮数据**看不出来**（4 次散布在 4 小时里，
  温度全程恒定，没有相关性可言）。
- ⚠ 温度恒定 34 °C **不能**推广到"这台臂不会热" —— 本档的占空比（每轮约 250 s、
  含 20 s 静置与大量静止段）可能根本不足以让它升起来。**要测热得上更重的占空比。**
