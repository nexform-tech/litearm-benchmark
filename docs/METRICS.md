# 指标字典

> ⚠ **本文件由 `scripts/gen_metrics_doc.py` 从指标注册表生成，不要手改。**
> 改指标请改 `src/litearm_benchmark/metrics/registry.py` 后重跑该脚本。

每个指标的阈值曲线都带 **出处**：是实测锚定的、物理推出的，还是**占位**（待标定）。
把占位当实测用，是这套体系里最容易犯、也最难发现的错。

## 静态精度与重复性

### `static.err_max_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  2→95  5→85  15→60  30→25  60→0`
- **出处**：实测锚定：2026-09-20 持位交接缺陷期间 J2 恒偏 **−12.6~−14.8 mrad**（判为缺陷）；同一台臂修复后 **+0.4 mrad**。⇒ 15 mrad 判 60 分、30 mrad 判 25 分。
- 说明：逐轴 `|落点均值 − 指令目标|` 的最大值；**基准必须用 clamp 后的目标**（目标越软限时固件会把锚点钳回限内，拿未钳目标比会假红）。

### `static.repeat_ptp_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0.1→100  0.8→90  2→75  5→50  12→20  25→0`
- **出处**：实测锚定：2026-09-18/20 同一台臂上 N 轮落点极差 **0.76~3.1 mrad**；位置编码器 LSB 本身 0.096 mrad ⇒ 低于 0.1 不可信。
- 说明：同一目标重复 N 轮的极差（**相对第 1 次落点**）。⚠ 它单独**不能**说明准确度 —— 每次都同样地偏在目标外时，它是 0。必须与 `static.err_max_mrad` 一起读。

### `static.floor_ratio`

- 单位：`×`　方向：**越小越好**　维度内权重：1
- 分数曲线：`1→100  1.3→90  2→75  4→45  8→15  15→0`
- 需要：`model`
- **出处**：**物理下界**：持位态内置前馈全停 ⇒ 稳态只由 `G(q_hold)` 与 `kp_hold·e` 平衡，库仑摩擦最多把臂拖开 `max(|fc0|,|fc1|)/kp_hold`（推导，`instruments.static_error_floor_rad`）。⇒ 该比值 **< 1 不可能**，锚点 1.0=100 分是对的。
- 说明：尺寸无关的**归一化**静差：`静差 / (fc0 / kp_hold)`。换机器/换固件后仍可比。

## 位置跟踪

### `track.rms_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→95  3→80  8→55  20→25  40→0`
- 需要：`hardware`, `log300`
- **出处**：实测锚定：修复后整条动作电池实测 rms **1.6~8 mrad**；修复前同一批（对齐口径正确时）在 10~40 mrad 量级。⚠ 历史 CSV 里 30~133 mrad 那组是**对齐失效**的产物，不可用作锚点。
- 说明：**跨流对齐后**的残差 rms（300Hz 参考 vs 100Hz 实测）。**必须同时看 `track.align_ratio`** —— 自证量不达标时这条数不可信。

### `track.peak_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  5→92  15→72  40→45  90→15  180→0`
- 需要：`hardware`, `log300`
- **出处**：同 `track.rms_mrad`（实测同批）。取残差绝对值峰值。

### `track.align_ratio`

- 单位：`×`　方向：**越大越好**　维度内权重：1
- 分数曲线：`1→0  2→55  3→80  5→95  8→100`
- 需要：`hardware`, `log300`
- **出处**：**自证量**：故意把时延再错开 80ms 的残差 / 最优时延下的残差。实测真结构 **3~6×**，离线随机负控 **1.00×** ⇒ 门槛取 2.0。
- 说明：**这条不是性能指标，是「上面两条跟跟踪有关的数可不可信」的闸门。** 低于 2× 时报告会把 `track.rms_mrad` 标成「不可信」而不是给低分。

### `track.lag_ms`

- 单位：`ms`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  8→90  20→70  45→40  90→10  150→0`
- 需要：`hardware`, `log300`
- **出处**：实测：修复后的动作电池里对齐 δ 落在 **−8 ~ −30 ms**（负=实测领先参考）。⚠ 它把**传输时延 + 伺服滞后 + 对齐估计误差**混在一起，不是纯伺服带宽。且**顶到搜索窗边缘时必须判为无效**（历史事故）。
- 说明：越小越好但**别过读**：它是复合量。

### `track.follow_p95_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  5→92  15→75  40→45  100→15  250→0`
- 需要：`hardware`
- **出处**：锚定到固件的**保护阈值**：跟随即误差判据在 `J1/J2=0.35 rad`、J3/J4=0.30、J5-J7=0.25（`safety_check.c`），且需**连续 5 周期**才锁存 ⇒ 250 mrad（0.25 rad）落到 0 分，0.35 rad 会直接触发保护。
- 说明：运动段 `|q − q_ref|` 的 p95。⚠ 直接用 100Hz 两流相减**有对齐误差**，故这里用 p95 而不是 max，且只在 `track.align_ratio` 达标时才报。

## 动态响应

### `dyn.overshoot_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  5→92  15→72  40→40  80→10  150→0`
- 需要：`hardware`
- **出处**：实测锚定：动作电池的越界峰 —— 中低速档 **5~10 mrad**、高速档（0.15 rad @ speed 1.0）**31~42 mrad**。
- 说明：落点越过目标的最大量（对**指令目标**取，不是对第一次落点）。

### `dyn.rebound_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  5→92  15→72  40→40  90→10  180→0`
- 需要：`hardware`
- **出处**：实测：回退幅度**恒 ≥ 0**（峰值后往回收的量）。中低速 0~7 mrad，高速档实测到 **62~68 mrad**。
- 说明：越峰之后**回退**的幅度。⚠ 与「越峰」是两个量，历史上混过一次。

### `dyn.settle_s`

- 单位：`s`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0.2→100  0.5→88  0.9→72  1.6→45  3→15  5→0`
- 需要：`hardware`
- **出处**：实测：小位移档 0.5~1.0s、大行程多轴 2.2s。锚点按这批的分布取。
- 说明：从发命令到进入并保持在到位带内的时间。

### `dyn.rise_ms`

- 单位：`ms`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  30→92  80→75  200→45  500→15  1000→0`
- 需要：`hardware`, `log300`
- **出处**：**占位** —— 尚未在多档速度上实测标定。它由固件的加速度/加加速度上限决定，换速度档会成比例变化 ⇒ 必须同档比。

## 平滑度与抖动

### `smooth.rest_sigma_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0.05→100  0.2→90  0.5→72  1.2→45  2.5→15  5→0`
- 需要：`hardware`
- **出处**：实测锚定：**对位置做直线拟合的残差 std** —— 根部 J1 ≈0.055 mrad（≈纯量化）、腕部 J6/J7 ≈0.13~0.17 mrad。⚠ 纯量化锯齿的理论 std = LSB/√12 = 0.028 mrad，实测腕部是它的 5~6 倍 ⇒ 真信号。
- 说明：**静止**时的位置抖动。⚠ 必须用**直线拟合残差**，不能从单频分量反推（历史上这样低估过 3~4 倍）。

### `smooth.rest_vs_quant`

- 单位：`×`　方向：**越小越好**　维度内权重：1
- 分数曲线：`1→100  2→88  4→70  8→40  16→10  30→0`
- 需要：`hardware`
- **出处**：**归一化**：抖动 std / (位置 LSB/√12)。纯量化锯齿 ⇒ 1.0。实测根部 ≈1（纯量化）、腕部 ≈5~6。
- 说明：尺寸无关版；换编码器位数后仍可比。

### `smooth.vel_ripple_pct`

- 单位：`%`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→92  4→78  10→55  20→25  40→0`
- 需要：`hardware`
- **出处**：实测锚定：**巡航段**速度纹波 3%(J1/J2) ~ 13%(J6/J7) 的巡航值，且与运动相关、到位后归零。⚠ 判「纹波」前须扣掉上报 dq 的量化地板。
- 说明：巡航段速度相对纹波 = std(v)/(|v|均值)。**必须取最长连续超阈段**切匀速段 —— 用首末下标会被收尾那一拍参考尖峰把窗拖进减速段（历史上把纹波虚高过 12 倍）。

### `smooth.jerk_spike_ratio`

- 单位：`×`　方向：**越小越好**　维度内权重：1
- 分数曲线：`1→100  2→90  4→72  8→45  16→15  32→0`
- 需要：`hardware`
- **出处**：**占位** —— 尚无多机型基线。定义：`max|Δv| / median|Δv|`（单流实测，不需要跨流对齐 ⇒ 无对齐伪影）。
- 说明：「顿一下」的量化指纹：某一拍速度突跳。单流指标，最干净。

### `smooth.tau_sigma_nm`

- 单位：`N·m`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  0.02→90  0.06→72  0.15→45  0.4→15  1→0`
- 需要：`hardware`, `log300`
- **出处**：**归一化请用 `smooth.tau_vs_quant`**；本条给出绝对值，锚点按 J5-J7 的细 LSB (0.0048) 与 J1/J2 的粗 LSB (0.0586) 之间取。⚠ 判抖动前**必须先扣掉量化地板** `LSB/√12`，否则把台阶当抖动。
- 说明：巡航段力矩 std，**已扣量化地板**（扣前会被 J1/J2 的粗 LSB 主导）。

### `smooth.tau_vs_quant`

- 单位：`×`　方向：**越小越好**　维度内权重：1
- 分数曲线：`1→100  2→88  4→68  8→38  16→10  30→0`
- 需要：`hardware`, `log300`
- **出处**：归一化版：力矩 std / (τ LSB/√12)。纯量化 ⇒ 1.0。

## 力矩

### `torque.peak_ratio`

- 单位：`×`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0.05→100  0.2→92  0.4→78  0.65→55  0.85→25  1→0`
- 需要：`hardware`
- **出处**：**物理锚定**：`tau_max` 是固件的硬钳位（`control_loop.c`），打到 1.0 就是饱和。实测动作电池的峰值占比在 0.05~0.25 之间，但**含过冲的档可到 0.65~0.75**。
- 说明：`max|τ| / tau_max`（逐轴取最大）。

### `torque.saturation_frac`

- 单位：`×`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  0.005→85  0.02→65  0.08→35  0.2→10  0.4→0`
- 需要：`hardware`
- **出处**：**物理定义**：`|τ| ≥ 0.98·tau_max` 的采样占比。非零就意味着某段在饱和 —— 饱和会引入非线性，是控制品质下降的直接证据。

### `torque.g_match_pct`

- 单位：`%`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  4→92  8→78  15→58  26→25  50→0`
- 需要：`model`
- **出处**：实测锚定：**静态**多姿态下 `τ_实测 vs G(q) 模型` 的偏差 —— 实测 **3.5% / 4.4% / 6.3% / 10.9% / 25.2%**（均值≈10%、中位 6.3%）。锚点直接贴这批分布。
- 说明：动力学模型的可信度。⚠ 必须在**稳态**读（装载/卸载的瞬态会把偏差读数高估一倍，历史上踩过）。

## 笛卡尔

- 单位：`mm`　方向：**越小越好**　维度内权重：1

- 说明：直线轨迹到理论直线的最大偏离。⚠ 比对精度**必须同姿态同负载**，否则数不可比。

### `cart.plan_us`

## 多轴同步

### `sync.stop_spread_ms`

- 单位：`ms`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  5→92  15→78  40→55  100→20  200→0`
- 需要：`hardware`, `log300`
- **出处**：**判据锚定**：正确的同步判据是「各轴**速度非零区间的停止**分散」，**不是**「全轴同乘一个速度系数」—— 后者已被实测证伪。固件 `movej_sync`(0x07) 的语义就是全轴同拍到达。⚠ 锚点为占位量级。
- 说明：`movej_sync` 下各轴到达时刻的极差。对比 `movej`（逐轴独立 S 曲线）应当显著更小。

## 热

### `thermal.t_mos_max`

- 单位：`°C`　方向：**越小越好**　维度内权重：1
- 分数曲线：`30→100  45→88  60→70  75→40  90→12  110→0`
- 需要：`hardware`
- **出处**：**器件锚定**：固件有温度预警通道（`temp_warning_cycles` 触发 `ARM_FLAG_TEMP_WARNING` 并单轴锁存）⇒ 接近预警阈值就是坏。锚点按 MOS 常见降额点取。
- 说明：全程 MOS 温度峰值。⚠ 温度只从 **100Hz 状态帧**取，日志里**没有**温度。

### `thermal.rise_per_min`

- 单位：`°C/min`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  0.5→88  1.5→70  3→42  6→12  12→0`
- 需要：`hardware`, `manual`
- **出处**：**占位** —— 需要长时间（≥20min）运行才能拟出斜率；项目实测里长时间运行的热是平的。

## 耐久与稳定性

### `endur.seq_gap`

- 单位：`帧`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→80  3→55  10→25  50→5  200→0`
- 需要：`hardware`
- **出处**：**可算准**：状态帧 `seq` 是 16-bit 计数器（65536 帧 ≈ 11 min @100Hz），`(seq2-seq1) mod 65536` 与该段步长×100Hz 对账即可。⚠ 判据必须**同时**报出「有几对可比」—— 只有 0 对时不能判绿。
- 说明：长时间运行中状态帧的缺口（掉帧/重连的量化证据）。

### `endur.reconnects`

- 单位：`次`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→40  2→15  5→0`
- 需要：`hardware`, `manual`
- **出处**：**期望恒 0**：一次长时间运行里不应出现任何意外重连。

### `endur.static_drift_mrad`

- 单位：`mrad`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→90  3→70  8→40  20→10  40→0`
- 需要：`hardware`, `manual`
- **出处**：**占位**：长时间运行前后**同一点位**的静差变化。它能把「热漂」「参数漂」「机械松动」三者混在一起 ⇒ 只作提示。

## 安全与保护

### `safe.watchdog_latency_s`

- 单位：`s`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0.1→100  0.2→88  0.35→65  0.6→35  1→10  2→0`
- 需要：`hardware`
- **出处**：**设计锚定**：固件命令看门狗超时是 **100ms**（`mode==MOVE_J` 时每拍自动 kick），实测跳闸 **0.21~0.29 s**。⇒ 2.0s 判 0 分。
- 说明：**停止发命令 → 观察到 fail-soft 生效**的时延。⚠ 判据要用 `flags & 0x2`（core 解成 `WD_TRIPPED`）——**按固件拼法搜 `WATCHDOG` 永远搜不到**（历史事故）。

### `safe.margin_rad`

- 单位：`rad`　方向：**越大越好**　维度内权重：1
- 分数曲线：`0.01→0  0.02→30  0.05→60  0.1→82  0.3→95  1→100`
- 需要：`hardware`
- **出处**：**设计锚定**：位置包络判定余量 0.05 rad、`POS_RECOVER_BAND` 0.05 rad，而 J4 的软限上界只有 **+0.0175 rad**（全轴最小）⇒ 0.02 rad 以下就该报警。
- 说明：运行全程**最小**的距软限裕度。⚠ 任何轴越限 ⇒ 整个笛卡尔面失效。

### `safe.pos_violation_events`

- 单位：`次`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→40  3→12  6→0`
- 需要：`hardware`
- **出处**：**期望恒 0**：位置越限锁存**不受 enabled 门控**、`reset` 也清不掉 ⇒ 出现即严重。

## 固件计算性能

### `compute.loop_max_kcycle`

- 单位：`kcycle`　方向：**越小越好**　维度内权重：1
- 分数曲线：`20→100  40→88  70→70  110→40  160→12  240→0`
- 需要：`hardware`
- **出处**：**硬件锚定**：控制拍周期 @300Hz = 480MHz/300 = **1600 kcycle**。峰值超过它就必然丢拍 ⇒ 锚点上限压在 240（已远超）。
- 说明：来自固件自检 `0x49` 的 `LOOP1` 段（DWT cycle）。**必须收满两帧**，否则便捷出口会静默返回 0。

### `compute.overruns`

- 单位：`拍`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→60  5→25  20→5  50→0`
- 需要：`hardware`
- **出处**：**期望恒 0**：控制拍超出预算的拍数。非 0 即控制周期被打破。

## 通信链路

### `link.status_hz`

- 单位：`Hz`　方向：**越大越好**　维度内权重：1
- 分数曲线：`60→0  90→50  98→85  100→92  105→100`
- 需要：`hardware`
- **出处**：**协议锚定**：被动状态帧固定 **100Hz** ⇒ 明显偏离 100 就是链路问题。实测 100.1Hz。高于 105 需要解释（重复计数？）。
- 说明：实测状态帧到达率。⚠ 用 `Msg.hz`（core 的到达统计）或自己按时间戳算。

### `link.crc_errors`

- 单位：`次`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→55  5→25  20→5  100→0`
- 需要：`hardware`
- **出处**：**期望恒 0**：固件 LINK 计数的 CRC 错误数。

### `link.foreign_frames`

- 单位：`帧`　方向：**越小越好**　维度内权重：1
- 分数曲线：`0→100  1→70  10→35  100→5  1000→0`
- 需要：`hardware`
- **出处**：实测事故：**广播抢帧**曾让读 RPC **21% 失败**（直连 0/200 vs 经 server 42/200）。⇒ 非 0 即说明有第二个会话在同一条链路上抢帧。

**取不到的量（指标会标「未实测」，不编分）**：

- `bus_voltage`：状态帧与电机反馈结构体都无电压字段（`dm_motor_drv.h` 的 fbpara 只有 state/pos/vel/tor/Kp/Kd/Tmos/Tcoil）⇒ **取不到**。

- `fk_arbitrary_q`：固件没有「给 q 求位姿」的下行命令；`get_tcp` 只能算当前反馈 q ⇒ **任意构型的 FK 取不到**（PC 侧要算须自己带运动学模型）。
